CONCLUSION
  The report is correct, but it is conditional on SV node policy configuration, not on version:
    * acceptnonstdoutputs=true  (post-Genesis DEFAULT)  -> bare OP_RETURN 0-sat is ACCEPTED
    * acceptnonstdoutputs=0                              -> REJECTED with "64: dust"
  Teranode accepts it under both. Arcade accepts it and reports it normally (RECEIVED ->
  ACCEPTED_BY_NETWORK -> MINED), so the teranode/arcade half of the report reproduces exactly.
  The distinction is provable unspendability: OP_FALSE OP_RETURN is provably unspendable and
  exempt from the dust check; a bare OP_RETURN output is spendable post-Genesis, so a 0-sat one
  is dust whenever the check is enforced.
  Note: -dustrelayfee and -dustlimitfactor are rejected by v1.2.2 as "removed" config options,
  so the threshold is no longer tunable -- but the dust RULE is still there, gated as above.
